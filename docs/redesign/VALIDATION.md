# 外部驗證計畫

狀態：尚未招募真人、未進行 A/B 實驗、未取得正式網站流量與表單回覆後台。以下是可交給活動團隊執行的流程，不是已發生的結果。

## 測試前固定的判斷標準

第一輪招募 24 位中山學生，主辦與非主辦系所各半，包含首次接觸活動者。隨機分成 A、B、C 三組，每組 8 位，每人只先看一種首屏。這是探索性測試，樣本不足以宣稱統計上的勝出。

學生測試先取得同意，不蒐集不必要的學號、電話與報名個資，不替受測者送出表單。

五秒測試逐字提問：
1. 看畫面五秒後收起頁面。
2. 「你覺得這是什麼活動？」
3. 「記得日期、地點或票價嗎？」
4. 「你會想繼續了解嗎？為什麼？」
5. 「哪裡讓你猶豫？」

第一輪標準：至少 7/8 能辨認活動類型，6/8 能記得日期或地點。記錄原話與錯誤，不提示標準答案。想參加的自述與實際報名行為分開記錄。

接著在手機完成四個任務：
- 找出自己的票價與三人團報價格
- 找出截止日與繳費方法
- 找到地點與入場時間
- 開啟正式報名表，停止於填寫或提交之前

初步標準：至少 7/8 在 30 秒內找到個人適用票價、截止日與付款義務，沒有把填表當成完成繳費。任務時間、錯誤、求助與放棄都記錄。不能只問喜不喜歡。

## 品牌窗口測試

由團隊招募 3 至 5 位有校園合作經驗的品牌窗口，請對方自行查看合作頁，再回答：受眾是誰、300 至 350 的數字代表什麼、有哪些合作方式、如何取得執行紀錄、如何聯絡。

通過標準：所有人都能辨識數字是預估，至少 4/5 能指出兩種合作項目與聯絡方式。如果只有 3 位，就保留個別觀察，不換算成有代表性的市場比例。記錄願意洽談前仍缺少的資料。

未經團隊授權，代理不主動傳訊息給學生或贊助商。

## 指標與資料來源

| 指標 | 計算方式 | 實際資料來源與限制 |
| --- | --- | --- |
| 報名入口點擊率 | 首頁工作階段中有點擊報名的工作階段 / 首頁工作階段 | 需接入經團隊同意的分析系統，目前未收集 |
| 表單開始率 | 有開始填寫的訪客 / 表單訪客 | 外部 Google 表單不能由本網站直接觀察，無工具時列為無法量測 |
| 表單送出數 | 官方表單實際回覆去重後的報名人數 | 需主辦方提供彙總，三人團報不能把一筆回覆算成一人 |
| 填表完成率 | 已送出人數 / 已開始填寫人數 | 缺分母就不計算，不以入口點擊冒充開始填表 |
| 繳費完成率 | 已確認繳費人數 / 有效報名人數 | 由主辦方彙總繳費紀錄，不把網站點擊當成付款 |
| 合作入口使用 | 合作頁瀏覽與聯絡點擊 | 聯絡點擊只能證明開啟 IG，不能代表已送訊息 |
| 有效贊助詢問 | 主辦方收到且與本活動合作相關的不重複詢問 | 以實際訊息彙整，排除重複與一般問題 |
| 分享使用 | 成功呼叫原生分享或複製網址 | 本站提供互動事件，不能證明朋友收到或看過 |
| 活動實到 | 現場實際簽到人數 | 與報名、繳費、企劃預估分開回報 |

第一輪版本 app.js 曾發出 `event:interaction` 瀏覽器事件。事件名稱有 registration_click、sponsor_view、sponsor_contact、instagram_click、calendar_download、share_complete。第二輪依使用者要求移除首頁分享功能，目前保留連結操作事件，表單頁行事曆連結仍可使用。沒有對外傳輸、cookie、持久儲存或分析後台。頁面本身也不會回報表單開始、送出與繳費事件。

接入分析時，要補上 page_view、工作階段分母、資料期間與清楚的隱私說明。不得送出 email、學號、表單答案或網址中的個人資料。

## 上線比較

先記錄一週基準與主要宣傳來源，再預先設定要比較的單一變因、主要指標、最小有用差異與停止規則。截止日前的搶票效應、卡司公告、票價與投放變動須標註。

流量足夠才採隨機 A/B 分流，讓同一訪客維持同一版本。依基準轉換與預期差異計算樣本量，不事後挑選好看的數字。樣本不足、追蹤缺漏或流量來源不平衡時，回報不確定，不宣布勝出。
