# 003 學生首屏候選方向

範圍：只比較現有素材支持的首頁首屏，尚未進行真人測試。

證據：src/event.mjs 已有日期、時間與飯店資訊，public/assets 有三聯童話插畫與 group、crowd、friends 歷年照片。現有 scripts/build.mjs 先展示橫向插畫，再於下方呈現標題與入口。

方向 A：保留插畫主題，改成文字與單幅插畫並列，手機先看日期、活動名、參加資訊入口，再看插畫。保留原活動辨識，首屏資訊較完整。

方向 B：歷年朋友合照作為主畫面，以小面積文字卡呈現日期、地點和入口。能直接看到真實學生參與，但必須持續標示 2025 紀錄，避免誤認今年現場。

方向 C：以大型 12.24 日期與票券式資訊為主，童話插畫作邊角視覺，照片下移至第二屏。操作最直接，但現有活動主視覺的吸引力會減弱。

建議：先實作 A，照片放緊接首屏的活動紀錄區。A 同時利用既有辨識與清楚資訊，B 適合作為後續五秒測試候選，C 可作資訊辨識基準。此比較屬設計推論，未證明 A 的報名轉換較高。

未知：學生對插畫或照片的偏好、首屏記憶率、票價接受程度。需實際五秒測試與任務操作比較。
